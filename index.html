When can it be seen?

If "until" is earlier than "from", the window runs past midnight (e.g. 22:00 to 02:00).

Don't show during

Add periods when no window should open, like all day Wednesday, or 18:00 to 10:00 on chosen days. A time range that ends earlier than it starts runs into the next morning. Any window that overlaps one is skipped.

Repeating locks re-seal themselves while this page is open during a window. Open the page at least once in every window. If a window passes without it, the number stays openable by technical means until you next open the page.

Unlock notifications

Sends a push notification through the free ntfy app when a lock unlocks, even with this page closed. The notification shows the lock's name, never its number.

How to set it up (one time per phone)
  1. Install the ntfy app.
  2. Make up a private channel name that nobody would guess, like tl- plus 10 random letters and numbers. Anyone who knows it can see your lock names.
  3. In ntfy, tap + and subscribe to that name on the default server, ntfy.sh.
  4. Enter the same name below and tap Save, then Send test.

Sending log for this phone

Every booking and cancellation this phone sent to ntfy in the last 3 days. Each one counts towards ntfy's free daily limit. The app stops at 50 a day per phone, and never repeats an identical send within 30 minutes.

Sync between devices

Keeps your locks the same on every device by saving them in a private GitHub repository. Only sealed copies are saved there, never a readable number.

How to set it up (one time)
  1. Create a private repository, for example timelock-data: github.com/new.
  2. Create an access key: new fine-grained token. Set the longest expiration offered. Under Repository access choose Only select repositories and pick that repository. Under Permissions, set Contents to Read and write. Generate it and copy it.
  3. Fill in both boxes below and tap Connect.
  4. On your other devices, use Copy setup link instead of repeating these steps.

Backup

Locks are saved in this browser. A backup lets you restore them after clearing browser data, or move them to another device. Every lock stays sealed in the backup. Restoring an unlocked lock needs an internet connection once to show its number again.

How it works

Your number is encrypted in this browser to a future round of drand, a public randomness network run by independent organizations. The key for each round is published only when that round arrives, every 3 seconds. Until then nobody can decrypt it: not you, not this site, not Claude. Changing your device clock doesn't help, because the key simply doesn't exist yet.

The number itself is never saved before it unlocks. Only the sealed version is. Unlocking needs an internet connection to fetch the published key.

Limits: once a number is shown, you know it. Repeating locks rely on this page re-sealing the number during each window. If drand stopped running before your unlock time, the number could not be recovered, so keep a separate backup of anything you can't afford to lose.
